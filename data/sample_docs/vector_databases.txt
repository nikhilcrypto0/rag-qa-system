Vector Databases: Architecture and Use Cases

A vector database is a specialized data store designed to efficiently store, index, and query high-dimensional embedding vectors. They are a core infrastructure component for AI applications, including semantic search, recommendation systems, and RAG pipelines.

What is a Vector Embedding?

A vector embedding is a numerical representation of data (text, images, audio) in a high-dimensional space. Semantically similar items are mapped to nearby points in this space. For example, the sentences "What is machine learning?" and "Explain ML concepts" would produce similar embeddings, even though they share no exact words.

Embeddings are typically generated by neural networks — for text, models like BERT, sentence-transformers, or OpenAI's text-embedding-ada-002 are commonly used.

Similarity Search

The primary operation in a vector database is approximate nearest neighbor (ANN) search: given a query vector, find the k most similar vectors in the store. This is distinct from exact nearest neighbor search (which is computationally infeasible at scale) and uses indexing structures like:
- HNSW (Hierarchical Navigable Small World): A graph-based index offering excellent recall/speed tradeoffs.
- IVF (Inverted File Index): Partitions the vector space into clusters for faster search.
- FAISS (Facebook AI Similarity Search): An open-source library by Meta that supports multiple index types. Suitable for in-process use or small-to-medium scale deployments.

Popular Vector Databases

1. Pinecone: Fully managed, serverless vector database. Supports metadata filtering, hybrid search, and real-time upserts. Widely used in production RAG systems.
2. Weaviate: Open-source vector database with a GraphQL API. Supports hybrid BM25+vector search natively.
3. Qdrant: High-performance open-source vector store written in Rust. Supports payload filtering and on-disk indexing.
4. Chroma: Lightweight, open-source, developer-friendly. Good for prototyping and local development.
5. pgvector: Extension for PostgreSQL that adds vector similarity search. Ideal when teams want to keep all data in a relational database.

Metadata Filtering

Vector databases support filtering on metadata fields alongside vector similarity search. For example, you might search for the top-5 most semantically similar documents that were also published after 2023 from a specific author. This combination of vector similarity and structured filters is called "filtered ANN search."

Indexing in a RAG System

In a RAG pipeline, the indexing workflow is:
1. Load and chunk documents.
2. Generate embeddings for each chunk using an encoder model.
3. Upsert (vector, metadata) pairs into the vector database.
4. At query time, encode the user query, search for top-k similar vectors, and retrieve the corresponding text chunks.

Dimension and Distance Metrics

The dimensionality of embeddings varies by model:
- all-MiniLM-L6-v2: 384 dimensions
- text-embedding-ada-002: 1536 dimensions
- nomic-embed-text: 768 dimensions

Common distance metrics:
- Cosine similarity: Measures the angle between vectors; insensitive to magnitude. Most commonly used for text.
- Euclidean distance (L2): Measures straight-line distance; sensitive to magnitude.
- Dot product: Efficient but assumes normalized vectors.
